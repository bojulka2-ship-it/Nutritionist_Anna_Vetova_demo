# Безопасность проекта

Краткий обзор защитных механизмов, что проверяется тестами и какие ограничения стоит знать.

## Что защищено и как

### Форма (клиент, `index.html`)

| Угроза | Защита |
|---|---|
| Спам-боты заполняют формы | **Honeypot-поле** `fSite` (`name="website"`): человек его не видит (поле за пределами экрана), бот заполняет → заявка выбрасывается с фейковым «успехом», на сервер ничего не уходит |
| Автоматическая отправка скриптом | **Time-ловушка**: если форма отправлена быстрее, чем за ~3 секунды после загрузки страницы, заявка отклоняется |
| Повторные отправки подряд | **Троттлинг**: не чаще 1 раза в 60 секунд на одну сессию (sessionStorage) |
| Невалидные данные | Клиентская валидация: имя ≥ 2 символов, телефон по маске `+7 (XXX) XXX-XX-XX`, контакт по формату канала, обязательное согласие |
| XSS через вводимые данные | Все пользовательские значения выводятся в DOM только через `textContent`; в коде нет `innerHTML`, `eval`, `document.write` |
| Подмена контакта (ссылки) | `normalizeContact()` режет ссылки (`t.me/…`, `vk.com/…`) до чистого ника и форматирует по каналу |

### Сервер (Google Apps Script, `Code.gs`)

| Угроза | Защита |
|---|---|
| Формула-инъекция в таблицу | Строка пишется через `setNumberFormat('@')` + `setValues` — значения вида `=1+1`, `=HYPERLINK(…)`, `+7 (…)` сохраняются **как текст** и не исполняются как формулы |
| Control-символы / переводы строк | `cleanStr()` заменяет их пробелами, схлопывает пробелы, `slice(0, max)` |
| Переполнение полей | Жёсткие лимиты длин: имя 60, телефон 11 цифр, контакт 120, программа 120, дата 40 |
| Чтение таблицы извне | `doGet()` всегда возвращает ошибку — через GET таблицу получить нельзя |
| Дубли заявок | Одинаковая пара имя+телефон в последних 25 строках не пишется повторно |
| Гонки при записи | `LockService.getScriptLock()` сериализует записи |
| Некорректный JSON | Возвращается ошибка, запись не происходит |

### Сбор как таковой

- Сайт без внешних зависимостей: шрифты, стили и скрипты — локальные. Нет CDN, нет трекеров/аналитики.
- Таблица сама по себе не публикуется: веб-приложение работает от имени владельца.

## Известные ограничения (важно для публикации)

1. **Публичный endpoint принимает POST от любого.** Honeypot и троттлинг — клиентские и
   обходятся прямым POST. На проде рекомендуется **не публиковать рабочий URL** в открытом
   коде (в этом репозитории `SHEETS_URL` — пустая заглушка). Серверного rate-limit для анонимов
   в Apps Script нет; при необходимости добавьте проверку по времени/IP внутри `doPost`.
2. **Согласие проверяется на клиенте.** Сервер сохраняет поле как «да»/пусто, но не
   отклоняет запись без него. Для юридической строгости решение — в политике сайта.
3. **Зависшие тесты.** `testDoPost` / `testInjection` в `Code.gs` пишут строки в таблицу —
   запускать только вручную для проверки.

## Тесты

```bash
node tests/security.test.js
```

34 проверки, покрывают: очистку/валидацию сервера, нормализацию контактов (сервер и клиент),
формула-инъекцию, отсутствие XSS-векторов и внешних ресурсов, антиспам-механики формы.
